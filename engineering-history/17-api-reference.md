# HTTP API reference

Generated by reading `app/main.py` on 22 Oct 2026 (pipeline v52) and
cross-checked against the running production instance. Every endpoint below
exists in the source; none is aspirational.

The API is **not** versioned or public. It exists for `web/index.html`, the
single-page review UI. Authentication is handled *outside* the app by Caddy
(HTTP basic auth); the app itself trusts the `X-Remote-User` header Caddy
sets. Running the app without that gate in front means every request is
unauthenticated — see "Authentication" below.

Base URL in production: `https://<your-static-ip>.nip.io`
Locally: `http://127.0.0.1:8077`

---

## Authentication and identity

Caddy terminates TLS, enforces basic auth against `gcp/users.caddy`, and sets
a single header:

```
header_up X-Remote-User {http.auth.user.id}
```

`app/main.py:_who(request)` reads that header and stamps it on every audit
record. The header is set by Caddy on each proxied request, so a client cannot
spoof it from outside — but **only because the app is not reachable except
through Caddy**. `docker-compose.prod.yml` enforces that: the app container
has `ports: !reset []` and is only `expose`d internally.

Run the app directly (`run.sh`, local development) and there is no gate at
all; `_who` falls back to a default actor.

## Endpoints

### Pages served

| Method | Path | Notes |
|---|---|---|
| `GET` | `/` | The review UI (`web/index.html`) |
| `GET` | `/cost` | Hidden cost page (`web/cost.html`). No link in the UI; same login |

### Status

| Method | Path | Returns |
|---|---|---|
| `GET` | `/api/health` | `ocr_ready`, `ocr_engine`, `roster_loaded`, `roster_size`, `templates`, `pipeline` (the `PIPELINE_VERSION` string), `workers`, `queue_depth`, `progress` |
| `GET` | `/api/me` | The signed-in person, from `X-Remote-User` |
| `GET` | `/api/log?after=<seq>` | Live activity feed for the UI; `after` is the last sequence the client saw |
| `GET` | `/api/accuracy` | The last benchmark run, scored against the client's typed Excel |
| `GET` | `/api/cost` | This GCP project's spend only. Exact when the BigQuery billing export is on, otherwise a list-price estimate — the response says which |

`/api/health` is the correct way to confirm which pipeline version is actually
**running**. Checking the files on disk is not sufficient: a `compose up -d`
can report "Container Running" without recycling the process, leaving new code
unused (recorded as a real incident in the runbook).

### Batches

| Method | Path | Notes |
|---|---|---|
| `POST` | `/api/batches` | Multipart upload. Fields: `name`, `files` (repeatable). Accepts PDF, JPG, PNG, TIFF. No limit on file count or page count; the only cap is Caddy's `max_size 512MB` per request |
| `GET` | `/api/batches` | All batches with per-status page counts |
| `GET` | `/api/batches/{batch_id}/pages?status=<s>` | Pages in a batch. `status=flagged` selects `needs_review`, `review_optional` and `error` together |
| `GET` | `/api/batches/{batch_id}/export?design=<d>` | Excel export. See `/api/export-designs` for valid values |
| `GET` | `/api/export-designs` | The available export layouts |

### Pages

| Method | Path | Notes |
|---|---|---|
| `GET` | `/api/pages/{page_id}?claim=<bool>` | The page record, issues and row confidence. `claim` also takes the edit lock |
| `GET` | `/api/pages/{page_id}/image` | The normalised page image |
| `PUT` | `/api/pages/{page_id}` | Save reviewer corrections, re-validate, and record every changed field in the audit log |
| `POST` | `/api/pages/{page_id}/reextract` | Force a fresh extraction, bypassing the cache |
| `POST` | `/api/pages/{page_id}/lock` | Renew or first-claim the edit lock while the page is on screen |
| `DELETE` | `/api/pages/{page_id}/lock` | Release the lock |

**Locking.** One person edits a page at a time. The lock is claimed on open,
renewed by heartbeat while the page is on screen, released on save or leave,
and expires after `db.LOCK_TTL_S` (300 s) of silence so a closed laptop never
freezes a page.

### Reference data

| Method | Path | Notes |
|---|---|---|
| `POST` | `/api/roster` | Upload a replacement employee list (CSV) |
| `GET` | `/api/audit?limit=<n>` | Change history, newest first. Default 300 |

## Behaviour worth knowing

**Extraction is cached by content.** The key is `page_hash` + `PIPELINE_VERSION`.
Re-uploading an identical page returns the cached result in about a
millisecond. Bumping `PIPELINE_VERSION` invalidates the whole cache by
construction, which is why every accuracy-affecting change must bump it —
otherwise a measurement silently scores the old code.

**`POST /api/pages/{id}/reextract` is the only way to bypass that cache** for a
page whose hash has not changed.

**Uploads are processed asynchronously** by a threaded worker pool sized by
`TS_WORKERS` (2 in production). `POST /api/batches` returns as soon as the
pages are queued; poll `/api/health` (`progress`, `queue_depth`) or
`/api/batches` for completion.

**Page status** is one of `pending`, `processing`, `clean`, `review_optional`,
`needs_review`, `corrected`, `error`. A `BLOCK` issue produces `needs_review`;
any other issue produces `review_optional`; a page is `clean` only when a
cross-check actually ran and reconciled — never merely because nothing
objected (D-078, D-091).

## Not implemented

Stated explicitly so nobody builds against them:

- No authentication endpoints. Auth is Caddy's, not the app's.
- No pagination on any list endpoint. `/api/batches` and
  `/api/batches/{id}/pages` return everything.
- No rate limiting inside the app.
- No webhook, callback or push notification on batch completion — the UI polls.
- No public or versioned API contract. These routes may change with the UI.
